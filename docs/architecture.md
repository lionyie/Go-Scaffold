# Architecture

[English](architecture.md) | [简体中文](architecture.zh-CN.md)

## Goals

- One repository can host multiple runnable ends (`apps/*`) and multiple backend services (`services/cmd/*`).
- Contracts are the source of truth; generated code is committed and verified in CI.
- Admin and RBAC are part of the default scaffold.
- Optional capabilities are extensions, not unconditional dependencies.

## Layers

```text
apps/web, apps/admin          Vue 3 + Vite + Vuetify 4
        │
        │  HTTP/JSON (protojson)
        ▼
services/internal/server      Kratos HTTP/gRPC, authn/authz, OAuth callbacks
services/internal/service     proto <-> biz adapters
services/internal/biz         usecases, repository interfaces
services/internal/data        GORM repositories, seed, health
services/internal/auth        JWT, password hashing, OAuth provider registry
services/internal/plugin      experimental runtime plugin loader
services/internal/webui       embedded web + admin SPA handler
        ▲
        │ generated by buf
contracts/proto/**/v1         protobuf contracts
```

Dependencies point downward only: `server → service → biz → data`. Extensions may
depend on `biz`, `data`, `server/authz`, and `extensions/registry`, but core code
must not import a specific extension.

## Boundaries

1. `contracts/` contains `.proto` files and `permissions.yaml` only. No Go or
   TypeScript implementation lives there.
2. `services/api/` is generated. The only hand-written file is
   `services/api/identity/v1/redact.go`, which must share the package with the
   generated request types.
3. `packages/api-client/src/generated/`,
   `packages/api-client/generated/`, `packages/shared/src/permissions.gen.ts`,
   and the `*_gen` packages under `services/internal/` are generated. Do not edit
   them.
4. `apps/*/dist`, `runtime-plugins/*/dist`, and
   `services/internal/webui/dist` are build output and are gitignored.
5. Each build unit owns its manifest: `services/go.mod`, every `package.json`,
   and `deploy/docker/Dockerfile`. Root files only orchestrate.

## Generated outputs

| Output | Source | Destination |
| --- | --- | --- |
| Go protobuf / gRPC / Kratos HTTP | `contracts/proto/**/v1` | `services/api/**/v1` |
| OpenAPI | `contracts/proto` | `packages/api-client/generated/openapi.yaml` |
| TypeScript schema | OpenAPI | `packages/api-client/src/generated/schema.d.ts` |
| Config schema | `services/internal/conf/conf.proto` | `services/internal/conf/conf.pb.go` |
| Permission constants | `contracts/permissions.yaml` | `services/internal/pkg/rbac/permissions_gen.go`, `packages/shared/src/permissions.gen.ts` |
| Wire DI | `services/cmd/api/wire.go` | `services/cmd/api/wire_gen.go` |
| Extension registries | `extensions/installed.lock.json` | generated `*_gen` packages and `features.gen.ts` |
| Web/admin bundles | `apps/*/dist` | `services/internal/webui/dist/{web,admin}` at packaging time |

## Extensions vs runtime plugins

- **Feature Extension**: compile-time code copied into the tree by
  `scripts/module.mjs`. It can add protobuf contracts, Go services, and pages.
- **Example**: a Feature Extension with `kind: "example"`. The bundled
  `example-notes` is a complete vertical slice.
- **Runtime Plugin**: a directory under `runtime-plugins/` loaded by the server
  at startup. It ships a manifest, browser ESM, and an optional static/proxy
  backend. The included `hello-panel` demonstrates a Vuetify page and a static
  API. It is marked experimental and is not part of MVP acceptance.
  Manifest `entry`/`styles` are relative to the plugin's `dist/`; the host serves
  them under `/proxy/plugins/<id>/frontend/`. Host apps install Vuetify globally,
  so plugins reuse the same component instances without bundling it.

Both extension registries are generated. Hand-written code imports only the
generated registry package, so installing or removing an extension never edits
core server or router files.

## Single binary, two SPAs

`make build` / `pnpm run build` embeds two builds:

- `/` → `apps/web/dist`
- `/admin/` → `apps/admin/dist`

`services/internal/webui` selects the mount by prefix and serves
`index.html` for history-mode routes. API and proxy prefixes never fall back to
an SPA.

## UI system

Both apps use Vuetify 4 with a shared theme from `packages/ui`:

- `scaffoldLight` and `scaffoldDark` themes, persisted in
  `localStorage["scaffold.theme"]` and switchable from the app bar.
- MDI icon set, pill buttons, rounded cards, and glass surfaces
  (`backdrop-filter`) for navigation and app bars.
- A shared `PageHeader`, snackbar, and confirmation dialog in
  `packages/ui` so both apps keep the same interaction language.
- Route transitions and card entrance animations; the login page uses an
  animated gradient background.

## Configuration

Runtime config lives in `configs/{config.local,docker,k8s}.yaml`. Environment
variables use the `SCAFFOLD_` prefix. Production startup refuses default JWT and
OAuth state secrets.
